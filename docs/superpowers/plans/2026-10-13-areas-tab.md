# Areas Tab Implementation Plan

**Verify:** `flutter test --exclude-tags "golden || scenario"`
**Setup:** `flutter pub get`
**Check:** `flutter analyze --fatal-infos`
**Final:** `flutter test --tags scenario test/scenario`
**Prototype:** C:\Users\cktra\Projects\opal\.superpowers\design\oura-ai-first-areas\project\Main.dc.html

**Goal:** The tab bar becomes Today / Areas / Workout / You. The Areas tab leads with the Move
and Routines rings, Pal's areas line, the `Also tracked` vital cards and a state dot on its tab.
All six area pages hang under it with the back label `Areas`, and Nutrition's old branch and
every moved path redirect.

**Architecture:** A new `Area` enum (six areas) is the single source for titles, glyphs and
which areas have a state rule. A pure `buildAreasSummary` turns today's numbers plus recent
history into the Areas tab's view model; the shell reads the same provider for the tab dot.
The shipped area page (`DetailScreen` over `buildAreaDetail`) is keyed by `Area` and gains
Nutrition, Sleep and Mood, the Routines list and the scene. A new `/areas` shell branch
replaces the Nutrition branch. Old paths become redirects, the way `/rituals`, `/sleep` and
`/mood` already are.

**Tech Stack:** Flutter, Riverpod 3 (codegen: `dart run build_runner build
--delete-conflicting-outputs` after changing a `@riverpod` function; the `.g.dart` files are
committed), go_router 16, flutter_test, scenario tests (`test/scenario`, tag `scenario`), goldens
(tag `golden`, machine-local, excluded from Verify).

**Design source.** No spec file: the canvas settles the design, and the decisions below were
approved in the `Spec review`. This run's canvas is the Prototype folder
`C:\Users\cktra\Projects\opal\.superpowers\design\oura-ai-first-areas\project\`, which holds one
board, `Main.dc.html`. The home-screen rings widget board is not part of this run; another run
owns it. The folder is gitignored and not in the worktree, so read it from its absolute path. In
its markup:
- `<sc-if value="{{onAreas}}">` is the Areas tab.
- `<sc-if value="{{focus.open}}">` is the area page.
- `<sc-if value="{{sub.isMeal}}">` is the meal detail; it already exists in the app and is not
  rebuilt.
- The `<nav aria-label="Tabs">` block is the tab bar with its dot.
- `showScene` says where the scene is drawn.

In its script, `areas`, `activityRings`, `vitals`, `focusOf`, `tabs`, `areasLabel`, `areasSaid`
and `backLabel` are the behaviour. Its numbers and sentences are sample data, and its inline
styles are the measurements. Read `DESIGN.md` sections 2 to 9 and section 11, decisions 2, 4 and
6. Out of scope: the canvas's You, Workout and Today views (shipped or owned by other runs), the
answer sheet, and the per-tab composer placeholder.

## Approved decisions (beyond the canvas)

1. **Areas layout follows the canvas.** Move and Routines are nested rings (152px, 16px stroke,
   radii 68 and 48, round caps, from 12 o'clock, area colours `move` and `rituals`, track the
   same colour at 0.2 alpha) with a legend row each: swatch, title, state word only when not On
   track, value. Then Pal's line, then `Also tracked` vital cards for Money, Nutrition, Sleep and
   Mood, then the caption `Dot is today. Band is where you usually are by this hour.` Every
   legend row and card opens its area page.
2. **Header count.** `N of 3 on track` counts Money, Move and Routines at On track or Ahead.
   Pal's line is built in code from the state rules, not a model call: with no area off,
   `Everything is on track.`; one off, `Money is worth a look.`; two, `Money and move are worth a
   look.`; three, `Money, move and routines are worth a look.` "Off" means Worth watching or
   Needs care. Titles after the first are lower case, and areas run in `Area` order.
3. **Tab dot.** 8px, at the icon's top right, ringed 2px in the bar surface. It shows when
   Money, Move or Routines is off: `care` ink if any Needs care, else `watch`. The tab's
   accessible label is then `Areas, money worth watching, move needs care` (off areas in
   `Area` order, title and state word lower case); otherwise `Areas`.
4. **Vital card range bar.** The dot is today's value so far. The band runs from the 25th to
   the 75th percentile (linear interpolation) of the same value at today's clock time on each of
   the previous 14 days that has any data of that kind. The band is left out when fewer than 7
   such days exist. Values per card:
   - **Money:** `$<left>` `left of $<budget>`, bar = left/budget. Over budget:
     `$<over>` `over $<budget>`, dot at 0. No budget: `$<spent>` `spent today`, with no bar.
   - **Nutrition:** kcal eaten so far (meal calorie mid, thousands separator), unit
     `kcal eaten so far`. The bar is scaled to the largest of today's value and the reference
     values.
   - **Mood:** the word (`moodWord`) for today's latest check-in, unit `at <h:mm AM>`, bar =
     pleasantness. The reference is each day's latest check-in at or before this clock time.
     With no check-in today the card reads `No check-in yet today` with no number and no bar.
   - **Sleep:** reads `No sleep data yet`, with no number and no bar.

   Nutrition, Sleep and Mood never show a state word, and their dot is `ink`. Money's dot and
   word take its state ink.
5. **Routes.** A new Areas branch sits at index 1. `/areas` has the children `money`, `move`,
   `routines` (child `manage`), `nutrition` (children `meal/:id`, `patterns`), `sleep` and
   `mood`. Workout keeps `/move`. Redirects keep the query string:
   - `/nutrition`, `/nutrition/meal/:id`, `/nutrition/patterns` -> the same under
     `/areas/nutrition`
   - `/today/spending` -> `/areas/money`
   - `/today/move-detail` -> `/areas/move`
   - `/today/rituals-detail`, `/today/rituals`, `/rituals` -> `/areas/routines`
   - `/today/rituals/manage`, `/rituals/manage` -> `/areas/routines/manage`
   - `/today/sleep`, `/sleep` -> `/areas/sleep`
   - `/today/mood`, `/mood` -> `/areas/mood`

   `/rituals/player/:routineId` is unchanged. The route names `nutritionMeal` and
   `nutritionPatterns` stay, because another run may use them.
6. **Area pages.** All six use the shipped area page layout. The back label is `Areas`
   (semantics `Back to Areas`), and the time-of-day scene (`DayScene`, as on Today) is drawn
   behind the top of the page. DESIGN.md section 6 changes to match: Today, the Areas tab and the
   area pages carry the scene, and sub-screens (meal detail, the routines builder) and the other
   tabs do not. The recent-entries list stays on Money, Move and Routines only.
7. **Routines page.** The contributors become `Done` (`N of M`, fraction N/M) and, when one is
   open, the next open routine (`<name>, <time>`, value `<n> steps`, fraction 0). Then comes
   `Today's routines`: each routine, in the rituals order, shows `Done` (`ink3`) or
   `<time> · <n> steps`. An open row pushes the routine player for that routine; a done row does
   nothing. The list ends with a `Manage routines` row with a chevron, which opens the routines
   builder at `/areas/routines/manage`.
8. **Nutrition page.**
   - Hero: kcal eaten today; unit `kcal eaten today`; no state word.
   - Pal line: `No meals logged yet today.`, `1 meal logged today.` or `<n> meals logged today.`
   - Contributors: Protein, Carbs and Fat in g. Each bar is that macro's share of today's macro
     calories (4/4/9 kcal per g), because there are no targets.
   - `Today's meals`: time, icon disc, name, kcal. Each row pushes the existing meal detail
     (`nutritionMeal`). Then `Add a meal`, which opens the existing `showNutritionAddSheet`.
   - Week bars: daily kcal, no goal line, week note `Kcal eaten each day`.
9. **Sleep page.** Header, scene, the `Sleep` title, then the empty state: `No sleep data yet`,
   with the line `Sleep needs a data source, and none is connected yet.` No view model and no
   chart. Seeded nights are not shown.
10. **Mood page.**
    - Hero: the latest check-in's word today, unit `at <h:mm AM>`. With no check-in today the
      hero is `—` and the unit `No check-in yet today`.
    - Pal line: `Last check-in at <h:mm AM>.` or `No check-in yet today.`
    - Contributors: today's check-ins, oldest first (label = time, value = word, fraction =
      pleasantness).
    - Week bars: the daily average pleasantness, no goal line, week note
      `Average of each day`.
    - No log button.
11. **Old screens go.** `NutritionScreen`, `SleepScreen` (with `sleep/widgets/sleep_widgets.dart`),
    `MoodScreen` and `RitualsScreen` are deleted with their tests and goldens. The old Nutrition
    tab's "expense looks like a meal" prompt goes with them. The mood logger sheet, meal detail,
    add and confirm sheets, nutrition widgets, patterns screen and all controllers stay.
12. **You tab.** Only the `Areas` group in `lib/screens/profile/profile_screen.dart` and its
    tests are removed. Nothing else in that file changes.
13. **Unchanged.** The composer/ask bar and Today. No paid entitlements are involved; this is
    plain Flutter UI and routing, safe for a free-account AltStore build.
14. **Not tappable on the area pages.** The canvas's Pal `Why`, contributor rows and week bars
    open the answer sheet, which is out of scope. On all six pages they stay as shipped: not
    tappable, with no `Why` button.
15. **Empty and loading states** (the canvas draws none):
    - **Areas tab loading:** the header with a quiet `…`.
    - **Areas tab error:** `Couldn't load your areas.`, logged with `debugPrint`.
    - **Nutrition with no meals today:** hero `0`, unit `kcal eaten today`, line
      `No meals logged yet today.`, macro bars at 0, no meal rows; `Add a meal` still shows.
    - **Routines with no routines:** hero `0`, unit `routines set up`, line
      `No routines set up yet.`, no `Done` contributor and no routine rows; the
      `Manage routines` row still shows.
16. **Where the plan departs from the canvas, by decision.** These follow DESIGN.md section 11,
    decisions 4 and 6, and were approved:
    - The canvas header reads `N of 6` and its Pal line counts Sleep. The app reads `N of 3` and
      counts only ruled areas.
    - The canvas gives Nutrition a 2,100 kcal goal. The app has no nutrition target.
    - The canvas draws Sleep with data. The app has no sleep data source.
    - The canvas reads Mood `n of 5`. The app uses the mood word.
    - The canvas routine rows and `Manage routines` have no action. The app gives them the
      actions in decision 7.

### Task 4: Areas summary view model
**Depends on:** Task 1
**Files:** `lib/controllers/areas_controller.dart`, `lib/controllers/areas_controller.g.dart`, `test/controllers/areas_controller_test.dart`

Implements decisions 2, 3 and 4 as pure code plus one provider. Reuse `moneyState` and
`progressState` from `lib/analysis/area_state.dart` and `GlanceNumbers` from
`lib/screens/today/today_logic.dart`. Do not copy the rules.

Interface:
```dart
@immutable class UsualBand { const UsualBand(this.low, this.high); final double low, high; } // 0..1
@immutable class AreaSummary {
  final Area area;
  final AreaState? state;      // null for areas without a state rule
  final String? number;        // null when the card shows only its unit line (Sleep, Mood with no check-in)
  final String unit;
  final double? progress;      // ring fraction (Move, Routines, unclamped) or bar dot 0..1; null = no bar
  final UsualBand? usual;      // null under 7 days of history, and for Move, Routines, Sleep
  final String semanticLabel;  // e.g. 'Money: $22 left of $60. Worth watching. Open Money'
}
@immutable class AreasSummary {
  final List<AreaSummary> areas;          // Area.values order
  AreaSummary of(Area area);
  int get onTrack;                        // ruled areas at good or thriving
  List<AreaSummary> get off;              // ruled areas at watch or care, Area order
  String get countLabel;                  // 'N of 3 on track'
  String get palLine;                     // decision 2
  AreaState? get tabDot;                  // care, watch or null (decision 3)
  String get tabSemanticLabel;            // decision 3
}
AreasSummary buildAreasSummary({
  required GlanceNumbers today,
  required List<Entry> entries,           // money history, for Money's band
  required List<NutritionMeal> meals,     // at least the last 15 days
  required List<MoodCheckin> checkins,    // at least the last 15 days
  required Currency currency,
  required DateTime now,
});
@riverpod Stream<AreasSummary> areasSummary(Ref ref);
```
The provider builds `GlanceNumbers` from `todayStateProvider` exactly as `today_screen.dart`
does (routines total = `routines.length`, done 0 when there are none). It reads entries, meals
and check-ins for the last 15 days from the existing repositories, and rebuilds when any of them
changes. Move's legend value is `<kcal> of <goal> kcal` (`<kcal> kcal` with no goal); Routines'
is `<done> of <total> done` (`<n> routines set up` with none). Expose those through `number` +
`unit`.
